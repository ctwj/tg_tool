# Feature Specification: 资源管理查看提取对比

**Feature Branch**: `016-resource-extraction-view`
**Created**: 2026-06-08
**Status**: Draft
**Input**: User description: "资源管理，添加一个查看按钮，点击查看，显示一个和采集器的记录列表中，资源提取一样的窗口，左侧显示原始的消息内容，右侧显示提取结果，用于查看，提取是否正确，我需要验证，提取的链接地址，和原始消息中的是否一致"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 查看资源提取结果对比 (Priority: P1)

用户在资源管理页面浏览已提取的资源列表，想验证某条资源的提取结果是否正确（特别是链接地址是否与原始消息一致）。用户点击该资源行的"查看"按钮，弹出一个左右分栏的对比窗口：左侧显示该资源对应的原始采集消息内容，右侧显示已提取的资源详情（标题、链接、描述、分类、标签）。用户通过对比左右两侧内容，确认提取的链接是否完整、是否有多余或遗漏。

**Why this priority**: 这是功能的核心价值——让用户能直观对比原始消息与提取结果，验证数据准确性。没有这个功能，用户无法有效检查提取质量。

**Independent Test**: 可以在资源列表页面对任意一条已提取资源点击"查看"按钮，弹窗正确显示原始消息和提取结果即可完整测试。

**Acceptance Scenarios**:

1. **Given** 资源管理页面有已提取的资源记录，**When** 用户点击某条资源的"查看"按钮，**Then** 弹出左右分栏的对比窗口，左侧显示原始采集消息文本，右侧显示该资源已提取的标题、链接列表、描述、分类、标签等信息
2. **Given** 资源记录有关联的采集历史（collector_history_id），**When** 查看弹窗加载时，**Then** 左侧从关联的采集历史中读取 raw_data 并展示原始消息内容
3. **Given** 资源记录无关联的采集历史（采集历史已被删除），**When** 查看弹窗加载时，**Then** 左侧显示"原始消息不可用"的提示，右侧仍正常显示提取结果
4. **Given** 原始消息中包含网盘链接（如夸克、百度、迅雷等），**When** 用户对比左右内容时，**Then** 可以清晰看到右侧提取的链接是否与左侧原始消息中的链接完全匹配

---

### User Story 2 - 快速关闭查看窗口 (Priority: P2)

用户查看完提取对比后，可以通过点击弹窗右上角关闭按钮、点击弹窗外区域、或按 ESC 键关闭查看窗口，返回资源列表继续操作。

**Why this priority**: 基本交互体验，确保用户能流畅地在多条资源间切换查看。

**Independent Test**: 打开查看弹窗后，通过三种方式（关闭按钮、点击遮罩、ESC）均可关闭弹窗。

**Acceptance Scenarios**:

1. **Given** 查看弹窗已打开，**When** 用户点击弹窗右上角关闭按钮，**Then** 弹窗关闭，焦点返回资源列表
2. **Given** 查看弹窗已打开，**When** 用户按 ESC 键，**Then** 弹窗关闭
3. **Given** 查看弹窗已打开，**When** 用户点击弹窗外的遮罩区域，**Then** 弹窗关闭

---

### Edge Cases

- 资源记录的 `collector_history_id` 对应的采集历史不存在（已删除）时，左侧显示不可用提示
- 资源记录的 `url` 字段为空时，右侧链接区域显示"无链接"
- 原始消息（raw_data）为空或仅包含空文本时，左侧显示空状态提示
- 多条资源关联同一条采集历史时，每条资源都能正确查看其对应的原始消息

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 资源管理列表的每行操作区域必须包含一个"查看"按钮
- **FR-002**: 点击"查看"按钮后，必须弹出与采集器资源提取弹窗风格一致的左右分栏对比窗口
- **FR-003**: 弹窗左侧必须显示该资源关联的原始采集消息内容（从 collector_histories 的 raw_data 中获取）
- **FR-004**: 弹窗右侧必须显示该资源已提取的完整信息：标题、链接列表、描述、分类、标签、提取模式
- **FR-005**: 弹窗必须为只读模式，不提供编辑或重新提取功能
- **FR-006**: 系统必须通过后端 API 根据资源 ID 获取关联的原始消息内容和提取结果
- **FR-007**: 当原始消息不可用时（采集历史已删除），左侧必须显示明确的不可用提示而非空白
- **FR-008**: 弹窗标题栏必须显示资源标题和创建时间，便于用户确认当前查看的是哪条资源

### Key Entities

- **ExtractedResource**: 已提取的资源记录，包含 collector_history_id 关联原始采集历史
- **CollectorHistory**: 采集历史记录，包含 raw_data（原始消息 JSON）、消息文本、媒体类型等
- **资源查看弹窗**: 只读对比窗口，左侧为原始消息，右侧为提取结果，数据来源于 ExtractedResource + CollectorHistory 的关联查询

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户可以在 3 秒内打开任意一条资源的查看弹窗并看到完整的对比内容
- **SC-002**: 用户能够通过左右对比，100% 直观地确认提取的链接是否与原始消息中的链接一致
- **SC-003**: 查看弹窗的交互体验（布局、样式、关闭方式）与现有的采集器资源提取弹窗保持一致，用户无需额外学习成本
- **SC-004**: 即使采集历史已被删除，查看弹窗仍能正常打开（右侧显示提取结果，左侧显示不可用提示）

## Assumptions

- 资源管理页面（Resources 页面）已存在且正常工作，本功能仅在其上添加查看按钮和弹窗
- 采集器资源提取弹窗的布局和样式可作为参考模板，新的查看弹窗复用相同的视觉风格
- 后端需要提供一个新的 API 接口，根据资源 ID 返回原始消息内容和提取结果
- 资源记录通过 `collector_history_id` 字段关联采集历史，此关联关系已存在且可靠
- 查看弹窗为纯只读展示，不涉及编辑、删除、重新提取等操作
